პროექტში არის core ნაწილი რომელზეც დაკავშირებულია ორი პლატფორმა web და android.

არის ორი რეპორტინგის სისტემა allure და extent რომელიც კონფიგურაციებიდან ყენდება.

პროექტში ყურადღება გამახვილებულია არა ტესტების რაოდენობაზე არამედ არქიტექტურაზე.
პროექტში დწერლი ტესტები არის რეკურსიული ალგორითმებით დაწერილი რომელიც mymarket–ის
დროპდაუნ ხის შემოვლას ეფუძნება. ხის შემოვლა ხდება ui დან და წამოღებული მონაცემების
შედარება ხდება category.json მონაცემთან სადაც 25 000 –ზე მეტი მონაცემია თავმოყრილი.

**აბსტრაქცია**
* კოდში არის 32 ინტერფეისი აქედან ბევრს მხოლოდ 1 იმპლემენტაცია აქვს. 
ინტერფეისები გამოვიყენე იმისთვის, რომ მომხმარებელი კოდში კონკრეტულ იმპლემენტაციაზე 
არ იყოს დამოკიდებული და ფრეიმვორქი სხვადასხვა პლატფორმისა და იმპლემენტაციისთვის მარტივად გაფართოებადი იყოს.
ზოგიერთ ინტერფეისს ამ ეტაპზე მხოლოდ ერთი იმპლემენტაცია აქვს, რადგან ის არქიტექტურულ კონტრაქტად გამოიყენება, 
ხოლო ზოგიერთს უკვე აქვს Web/Mobile-ის ან რეპორტინგის სხვადასხვა იმპლემენტაცია.

* არქიტექტურა ისეა დაგეგმილი, რომ მომავალში iOS-ის მხარდაჭერის დამატება შესაძლებელი იყოს ბიზნეს-დონის კონტრაქტების შეცვლის გარეშე.


მონაცემების სისწორე მნიშვნელოვანი არ არის ამ ეტაპზე, რადგან პროექტი არის სადემონსტრაციო.
ის ქეისები რომელებიც ამჟამად ფეილდება მაგალთად ui–ზე კატეგორიის სახელი არ უდრის მოსალოდნელ შედეგს,
ეს გამიზნულად არის შეცვლილი ტესტირების შედეგის მისაღებად.

## Core


### asserts
- **BrandVerifier** — ამოწმებს, არსებობს თუ არა ბრენდები კატალოგში და აბრუნებს შედეგს

### config
- **ConfigSource** — კონფიგურაციის მთავარი წყარო (properties-ებიდან კითხულობს)

- **ITimeoutConfig** — ლოდინის დროების კონფიგი
- **IUrlConfig** — URL-ების კონფიგურაცია
- **IWait** — explicit/implicit wait-ების პარამეტრები
- **TypedPropertiesHelper** — properties ფაილიდან typed მნიშვნელობების წაკითხვა

### exception
